Privacy Policy - Mind Map Module
Product: LÚMEN
Module ID: modulo_mapamental
Last updated: November 22, 2026
Version: 2026.11.22.0

This Policy describes how the Mind Map module handles information when used with LÚMEN. The module is designed for local creation of maps, notes, concepts, file links, and generation assisted by local processing. This Policy is specific to the module and should be read together with the Privacy Policy of the parent application.

1. Scope and principles
- Local operation: Mind Map data remains on the device, except when the Microsoft Store processes acquisition, licensing, or payment for the module.
- Minimization: the module handles only content needed to create, edit, save, load, export, and generate mind maps.
- User control: you choose which documents to import, which maps to save, which images to export, and which files to link.

2. Data handled by the module
2.1 Map content
- Concepts, notes, summaries, relationships between nodes, colors, positions, hierarchy levels, layout mode, and navigation state.
- Local paths of files linked to map nodes.
- Tasks or records derived when there is local integration with the parent application.

2.2 Documents chosen by the user
- When you import a document, the module reads the selected file to extract text and create a map structure.
- Supported formats may include PDF, EPUB, DOC, DOCX, TXT, MD, CSV, XLSX, JSON, DB, SQLite, and XML, depending on the resources available in the package.
- The module does not automatically scan folders; it processes only files chosen by you.

2.3 Local AI processing
- When local AI resources are available, the module may use local runtimes such as llama.cpp/GGML, CPU/Vulkan, local models, and auxiliary files.
- Document text may be copied to temporary prompt/schema files during local processing and automatically removed at the end of the temporary cycle when technically possible.
- Local AI processing does not send documents to the developer.

2.4 Local technical data
- The module may keep mapamental_config.json, mapa_mental_autosave.json, maps saved by the user, local model paths, temporary processing files, and local error logs.

3. Purposes of processing
- Create, edit, save, and load mind maps.
- Export PNG images and JSON files when requested.
- Generate maps from documents chosen by the user.
- Restore layout preferences and local autosave.
- Integrate local data with the parent application when the user uses synchronization features.

4. What the module does not do
- It does not create its own account, registration, or login.
- It does not collect automatic telemetry.
- It does not send documents, maps, notes, images, or models to the developer.
- It does not scan user folders beyond the files you choose to open/import.
- It does not access payment data; payments and licenses are processed by the Microsoft Store.

5. Microsoft Store, purchase, and license
- Module acquisition, license confirmation, and any payments are processed by the Microsoft Store, the user's Microsoft account, and Microsoft's systems.
- The application queries the Microsoft Store to verify whether the plugin_mapamental module license is active.
- The developer does not receive or store full payment data, Microsoft account credentials, or banking information.
- Data handled by Microsoft in these flows is subject to Microsoft's privacy policy and terms.

6. Storage and retention
- Maps saved as JSON and images exported as PNG remain in the location you choose.
- Local autosaves and preferences may remain in mapa_mental_autosave.json and mapamental_config.json until you clear, replace, or delete those files.
- Temporary files are intended for processing and may disappear at the end of the session; system failures or files in use may require manual cleanup.

7. Sharing
- The module does not share data with third parties on its own initiative.
- Integration with the Eisenhower workflow, Pomodoro, or Feynman occurs locally within the same installation.
- Any external sharing occurs only through user action, for example by exporting images, saving maps, copying content, or sending documents to third parties.

8. Security
- Because data is stored on the device, protection depends on the safeguards of the operating system, user permissions, antivirus software, local encryption when configured, and backups.
- Imported documents may contain sensitive information; we recommend storing maps and exports in protected locations.
- We recommend keeping Windows, the Microsoft Store, graphics drivers, and the application up to date.

9. User rights and controls
- You can edit, clear, save, export, and delete maps through the interface or by removing local files.
- You can remove file links and manually delete local autosaves/preferences.
- You can uninstall the module or the application to remove installed files; persistent local data may require manual cleanup depending on the system's behavior.

10. Children and adolescents
- The module is not directed to children under 13 and does not intentionally collect personal data.

11. Changes to this Policy
- This Policy may be updated when the module receives new features, integrations, or relevant changes in data handling.

INDEPENDENCE FROM MICROSOFT PRIVACY STATEMENT AND SUPPORT AND ON-DEMAND NETWORK TRANSPARENCY
1. Independence from Microsoft (Microsoft Store Policy 10.5): Microsoft does NOT provide a default privacy policy for LÚMEN, and this application is NOT covered by Microsoft's Privacy Statement. Microsoft does not provide customer support (developer contact: linceu_lighthouse@outlook.com | https://github.com/fernandoncidade/Eisenhower_Organizer_Lumen_cpp).
2. Local Storage Paths: User files live under %LOCALAPPDATA%\Lumen (tarefas.json, tarefas.json.bak, conceitos_feynman.json, mapa_mental_autosave.json, listas.db in Agenda, gantt_database.db in Gantt, and logs/file_*.log) with zero telemetry and zero mandatory accounts.
3. Optional User-Initiated Network Operations:
   - Local AI Model (Qwen 2.5 GGUF): optional HTTPS download from Hugging Face (with HTTP Range pause/resume and disk deletion); subsequent llama.cpp inference sends zero data externally.
   - Local Ollama: strictly loopback HTTP queries to http://127.0.0.1:11434 when triggered by the user.
   - Edge TTS (Audiobook): selected reading text is sent to the speech service only when the user explicitly selects an online voice; local Windows SAPI voices stay 100% offline.
   - Gantt REST API / Webhooks: disabled by default; listens or dispatches events only when explicitly enabled by the user with SecurityService.
